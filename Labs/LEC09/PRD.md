# Sonic 애니메이션 뷰어 PRD

## 1. 문서 정보

- 제품명: Sonic Animation Viewer
- 대상 경로: `Labs/LEC09/sonic_animation_viewer.py`
- 입력 스프라이트: `Labs/LEC09/sonic-sprite.png`
- 실행 환경: Python, Pico2D
- 상태: 개발 전 요구사항 정의
- 기준 문서: `Labs/LEC09/PRE_PRD.md`

## 2. 제품 개요

스프라이트 시트에 포함된 Sonic의 동작을 순서대로 보여주는 데스크톱 애니메이션 뷰어를 만든다. 창 크기는 1200×600이며, 캐릭터는 시작 시 화면 중앙에 원본 프레임 크기의 3배로 표시한다. 각 동작은 5회 반복하고 0.5초 정지한 뒤 다음 동작으로 넘어간다. 프레임 이미지는 0.1초 간격으로 표시한다. 이동 동작에서는 해당 동작의 방향으로 캐릭터가 이동하고, 좌측 이동 시 원본 프레임을 수평 반전한다. 캐릭터가 화면 끝에 닿으면 위치를 중앙으로 초기화하되 프레임, 반복 횟수, 액션 상태는 유지해 애니메이션을 계속한다. 시트의 모든 동작을 재생한 후에는 처음 동작부터 같은 순서를 무한 반복한다.

## 3. 목표와 범위

### 목표

- Pico2D로 지정 스프라이트 시트를 읽고 프레임 단위 애니메이션을 재생한다.
- 동작별 반복, 정지, 전환 순서를 일정하게 유지한다.
- 이동 방향에 맞춰 캐릭터를 움직이고 좌측 이동 프레임을 수평 반전한다.
- 화면 끝에 닿으면 캐릭터를 중앙으로 옮기고 기존 애니메이션을 이어간다.
- 최소 20개의 검증 가능한 점진적 개발 단계를 수행하고, 단계마다 테스트 후 커밋한다.
- 모든 커밋 메시지는 한글로 작성한다.

### 현재 구현 확인 기록

- 실행 명령: `python sonic_animation_viewer.py` (`Labs/LEC09`에서 Pico2D가 설치된 Python 환경 사용)
- 단위 테스트 명령: `python -m unittest -v test_sonic_animation_viewer`
- 확인된 원본 시트는 399×525 픽셀의 투명 PNG다. 기존 코드가 사용하던 첫 8개 스트립에 더해 미사용 프레임 스트립 y=377~416(8프레임), y=426~468(4프레임)을 확인했다. y=472 이후의 크레딧 아트는 동작 프레임에서 제외한다.
- 전체 동작 프레임 수는 순서대로 11, 12, 6, 9, 6, 6, 6, 8, 8, 4개다. 시트에 액션명이 없어 `동작 1`~`동작 10`으로 관리한다.
- 이동 방향은 프레임 포즈 기준 동작 1과 3~7, 9는 오른쪽, 동작 2는 왼쪽, 동작 8과 10은 제자리로 분류한다. 동작 2 프레임은 Pico2D 수평 반전으로 표시한다.
- 화면 경계 접촉 시 캐릭터 위치를 중앙으로 초기화하되 현재 프레임·반복 횟수·액션 상태는 유지한다.
- 이동 속도 기본값은 120픽셀/초다. 통합 검사에서는 확장된 전체 액션 순서에서 5회 반복, 0.5초 정지, 좌우반전, 중앙 복귀 후 재생 지속, 마지막에서 첫 동작 순환을 확인한다.
- 10개 동작의 총 프레임 수는 76개이며, 5회 반복 통합 사이클에서는 380개 프레임을 재생한다.

### 범위에 포함

- 스프라이트 시트에서 동작별 프레임과 원본 좌표를 확인한다.
- 프레임을 잘라 1200×600 화면에 원본 크기의 3배로 그린다.
- 이동 방향이 왼쪽이면 원본 프레임을 좌우 반전해 표시한다.
- 코드에서 사용하지 않던 시트 내 프레임 스트립도 조사해 동작 9와 동작 10으로 재생한다.
- 각 애니메이션 프레임 이미지의 스프라이트 원본 좌표와 프레임 표시 간격을 명시한다.
- 이동 액션별 이동 방향과 속도를 데이터로 정의하고 화면 경계 동작을 처리한다.
- 한 동작을 정확히 5회 완주한 뒤 0.5초 대기한다.
- 동작을 시트 정의 순서로 전환하고 마지막 동작 뒤 첫 동작으로 돌아간다.
- 창 닫기 요청을 처리하고 Pico2D 리소스를 정리한다.

### 범위에 미포함

- 플레이어 입력 조작
- 스프라이트 시트 이미지 자체의 편집 또는 재제작
- 배경, 점수, 게임 규칙, 사운드 추가
- 재생 속도나 확대 배율을 조작하는 사용자 설정 UI

## 4. 사용자와 사용 시나리오

주 사용자는 LEC09 애니메이션 실습을 진행하는 개발자다.

1. `Labs/LEC09`에서 `sonic_animation_viewer.py`를 실행한다.
2. 1200×600 창이 열리고 `sonic-sprite.png`가 로드된다.
3. 첫 동작의 첫 프레임이 시작 위치인 화면 중앙에 원본 크기의 3배로 표시된다.
4. 각 프레임 이미지를 0.1초 간격으로 표시하며, 각 동작을 5회 재생한다.
5. 이동 동작 중에는 동작 방향으로 캐릭터가 이동한다. 좌측 이동 시 프레임은 좌우 반전된다.
6. 캐릭터 외곽이 어느 화면 끝에 닿으면 위치를 `(600, 300)`으로 초기화하고 현재 액션과 프레임 재생은 이어간다.
7. 동작 완료 후 0.5초 동안 마지막 프레임을 유지한다.
8. 다음 동작을 재생하고, 마지막 동작 뒤에는 첫 동작부터 반복한다.
9. 창 닫기 요청 시 실행을 종료하고 화면 및 이미지 리소스를 정리한다.

## 5. 기능 요구사항

### FR-1. 스프라이트 로드

- 실행 파일은 LEC09 스프라이트 파일을 상대 경로로 불러온다.
- 이미지가 없거나 읽을 수 없으면 오류 원인을 확인할 수 있어야 하며, 조용히 잘못된 프레임을 출력해서는 안 된다.

### FR-2. 동작 및 프레임 정의

- 스프라이트 시트를 실제 이미지 기준으로 분석해 동작의 재생 순서와 프레임별 원본 사각형 `(x, y, width, height)`을 정의한다.
- 프레임의 행·열, 프레임 수, 프레임 크기가 동일하다고 미리 가정하지 않는다.
- 실제 표시할 프레임별 이미지 목록과 원본 사각형 `(x, y, width, height)`을 액션별로 기록한다. 시트에 인쇄된 제목, 설명, 크레딧은 애니메이션 프레임에서 제외한다.
- 현재 코드에서 사용되지 않았던 y=377~416 및 y=426~468의 그림 스트립을 각각 액션 9와 액션 10으로 추가한다.
- 모든 프레임 사각형은 이미지 경계 안에 있어야 한다.

### FR-3. 창 크기, 배치 및 크기

- Pico2D 창 크기는 가로 1200픽셀, 세로 600픽셀이다.
- 캐릭터 시작 위치는 캔버스의 기하학적 중앙 `(600, 300)`이다.
- 각 프레임은 자신의 원본 가로·세로 크기를 기준으로 각각 3배 확대한다.
- 확대된 프레임의 중심을 캐릭터 위치에 맞추고 원본 비율을 유지한다.
- 3배 확대 결과가 캔버스를 벗어나는 경우 요구사항을 임의로 낮추지 말고, 클리핑 정책을 구현 전에 결정한다.

### FR-4. 프레임 재생

- 현재 동작에 정의된 프레임을 순서대로 표시한다.
- 마지막 프레임 다음에는 같은 동작의 첫 프레임으로 돌아간다.
- 프레임 이미지 간 표시 간격은 0.1초(100ms)로 고정한다.
- 시간 간격은 렌더 루프 실행 속도에 좌우되지 않아야 한다. 프레임 변경은 경과 시간을 기준으로 갱신한다.

### FR-5. 반복, 대기 및 전환

- 한 번의 반복은 현재 동작의 프레임 목록 전체를 한 차례 재생하는 것이다.
- 각 동작을 정확히 5회 반복한 후 0.5초 대기한다.
- 대기 중에는 현재 동작의 마지막 표시 프레임을 유지한다.
- 대기 완료 후 다음 동작의 첫 프레임부터 시작한다.
- 마지막 동작 완료 후에도 같은 대기를 거친 뒤 첫 동작으로 돌아가 무한 반복한다.

### FR-6. 이동 동작 및 화면 경계

- 스프라이트 시트 분석 결과로 액션을 정지 동작 또는 이동 동작으로 분류한다.
- 각 이동 동작에는 방향(좌/우/상/하 또는 대각선)과 이동 속도를 명시한다. 동작별 속도는 설정 데이터에서 관리한다. PRE_PRD에 수치가 없으므로 초기 기본값은 120픽셀/초로 두고 실제 실행 검증에서 확인한다.
- 이동은 프레임 인덱스에 종속된 고정 이동량이 아니라 경과 시간을 기준으로 적용해 FPS에 좌우되지 않게 한다.
- 확대된 캐릭터의 외곽이 이동 중 어느 화면 경계에 닿으면 캐릭터 중심을 `(600, 300)`으로 즉시 초기화한다.
- 중앙 복귀는 위치만 바꾸며, 현재 동작·프레임 인덱스·완주 횟수·재생/정지 상태는 초기화하지 않는다. 기존 애니메이션이 다음 프레임부터 계속 진행한다.
- 화면 끝에서 중앙으로 이동한 뒤 같은 방향 이동이 계속되어 경계에 다시 닿으면 동일하게 중앙으로 복귀한다.
- 정지 동작에서는 캐릭터의 위치를 이동시키지 않는다.

### FR-7. 좌측 이동 프레임 반전

- 이동 방향이 왼쪽인 액션은 프레임 원본 사각형을 유지하고 Pico2D 수평 반전으로 표시한다.
- 원본 스프라이트 이미지나 프레임 데이터를 별도로 뒤집거나 복제하지 않는다.
- 우측 이동과 정지 액션은 반전하지 않는다.

### FR-8. 종료 및 정리

- 창 닫기 이벤트를 반복 재생 중과 정지 중 모두 처리한다.
- 종료 시 Pico2D 캔버스와 사용 중인 이미지 리소스를 정리한다.

## 6. 비기능 요구사항

- Python과 Pico2D 외에 별도 애니메이션 라이브러리를 추가하지 않는다.
- 창 크기, 프레임 좌표, 프레임 간격, 반복 횟수, 대기 시간, 동작별 이동 방향과 속도는 이름 있는 상수 또는 명시적 동작 데이터로 관리한다.
- 반복·정지·전환 로직은 창을 막아 종료 이벤트를 놓치지 않도록 시간 기반 갱신 방식으로 구현한다.
- 코드와 테스트는 프레임 데이터와 상태 전이를 분리해 확인할 수 있어야 한다.

## 7. 입력 자산과 확인 사항

- 현재 LEC09 폴더에 확인된 파일명은 `sonic-sprite.png`다.
- PRE_PRD에는 `sonic_sprite.png`로 기재되어 있어 하이픈/밑줄 표기가 다르다. 구현 시 실제 파일명을 기준으로 통일하며, 필요하면 파일 이름 변경 여부를 별도로 결정한다.
- 스프라이트 시트는 399×525 픽셀이다. 제목 및 크레딧을 제외한 액션 프레임 스트립 10개를 분석해 사용한다.
- y=377~416과 y=426~468의 미사용 이미지 스트립도 각각 8개, 4개 프레임으로 액션 목록에 포함한다.
- 프레임 이미지 목록과 각 이미지 간격은 액션별로 기록한다. 모든 액션의 간격은 초기 요구사항상 0.1초다.
- 시트에 보이는 제목 및 크레딧 문구와 여백이 프레임에 포함되지 않도록 프레임 경계를 확인한다.
- 확대 3배 결과와 캐릭터가 이동할 때의 경계 계산을 1200×600 캔버스에서 확인한다.
- 좌측 이동은 Pico2D의 수평 반전 렌더링을 사용한다.
- 화면 끝 도달 정책은 위치 제한이 아니라 중앙 `(600, 300)` 복귀다. 액션 상태와 프레임 재생은 유지한다.
- 이동 속도 기본값 120픽셀/초는 PRE_PRD에 명시되지 않은 초기 설계값이므로 실제 실행 검증에서 조정 가능하다.

## 8. 검증 계획

- 정적 검사: Python 문법 검사와 편집기 진단을 통과한다.
- 자산 검사: 모든 프레임 사각형이 원본 이미지 경계 안에 있는지 검사한다.
- 렌더 검사: 대표 프레임을 Pico2D로 잘라 그려 위치, 크기, 비율을 확인한다.
- 프레임 간격 검사: 프레임 이미지 변경 시각이 0.1초 간격인지 확인한다.
- 창 크기 검사: Pico2D 캔버스가 1200×600인지 확인한다.
- 상태 검사: 동작별 프레임 수가 달라도 마지막 프레임에서만 완주 횟수가 증가하는지 확인한다.
- 반복 검사: 임의의 동작에서 프레임 전체 순환을 5회 완료했을 때만 정지 상태로 바뀌는지 확인한다.
- 대기 검사: 0.5초 이전에는 다음 동작으로 넘어가지 않고, 만료 시 다음 동작의 첫 프레임으로 초기화되는지 확인한다.
- 순환 검사: 전체 동작 순서를 두 바퀴 이상 실행해 마지막에서 첫 동작으로 이어지는지 확인한다.
- 이동 검사: 이동 액션이 설정된 방향과 속도로 움직이고, 정지 액션은 위치를 유지하는지 확인한다.
- 좌우반전 검사: 좌측 액션은 Pico2D 수평 반전으로 그려지고 우측/정지 액션은 반전되지 않는지 확인한다.
- 미사용 프레임 검사: 추가한 액션 9와 10의 모든 프레임이 순서대로 표시되는지 확인한다.
- 경계 검사: 캐릭터 외곽이 화면 끝에 닿을 때 중심으로 복귀하고, 기존 프레임·완주 횟수·재생 상태가 유지되는지 확인한다.
- 종료 검사: 재생과 정지 각각에서 창 닫기 요청 후 정리 경로가 실행되는지 확인한다.
- 실제 실행 검사: LEC09 디렉터리에서 Pico2D로 뷰어를 실행해 전체 시트 동작을 확인한다.

## 9. 완료 기준

- `Labs/LEC09/sonic_animation_viewer.py`가 지정한 스프라이트 파일을 읽고 실행된다.
- 실행 창 크기가 1200×600이다.
- 스프라이트 시트에 확인된 모든 동작이 순서대로 재생된다.
- 액션별 사용 프레임 이미지와 원본 사각형이 기록되어 있고, 프레임 간격은 0.1초다.
- 각 동작이 정확히 5회 재생되고 동작 사이에 0.5초 정지한다.
- 마지막 동작 이후 첫 동작으로 돌아가 계속 재생된다.
- 모든 프레임이 시작 시 중앙에서 원본 크기의 3배로 표시되며 원본 비율이 유지된다.
- 좌측 이동 액션은 원본 프레임을 수평 반전해 표시하고, 우측/정지 액션은 반전하지 않는다.
- 기존 미사용 스트립의 액션 9(8프레임)와 액션 10(4프레임)이 재생 순서에 포함된다.
- 이동 액션이 화면 끝에 닿으면 중심으로 복귀하며 기존 액션과 프레임 재생은 계속된다.
- 프레임 경계, 반복 수, 정지 시간, 동작 전환, 순환, 종료 검증을 통과한다.
- 점진적 구현의 각 단계가 테스트 및 개별 커밋으로 기록되고, 개발 종료 시 최소 20개의 작업 커밋이 확인된다.
- 모든 커밋 메시지는 한글로 작성한다.
