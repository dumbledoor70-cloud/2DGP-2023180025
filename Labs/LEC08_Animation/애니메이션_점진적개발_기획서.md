# Mario 애니메이션 뷰어 점진적 개발 기획서

## 1. 목표

`mario.png` 스프라이트 시트의 5가지 액션을 화면 중앙에서 차례로 재생한다. 각 액션은 한 번의 애니메이션 재생을 5회 반복한 뒤 1초 동안 멈추고, 다음 액션으로 전환한다. 다섯 액션을 모두 재생하면 첫 액션으로 돌아가 이를 무한 반복한다. 캐릭터는 원본 비율을 유지하면서 800×600 화면에 알맞은 크기로 확대한다.

## 2. 시작 기준과 전제

- 시작 커밋: `d6a25341109cd6d3d3835014ea753b316879982e` (`오른쪽 달리기`)
- 이 기준 커밋에는 `Labs/LEC08_Animation/animation_viewers.py`가 없으므로 개발 과정에서 새로 만든다.
- 기준 커밋 이후의 로컬 커밋은 작업 기준에서 제외한다.
- `Labs/LEC08_Animation/mario.png`는 기준 커밋 이후의 기획서 커밋에 원본 자산으로 포함되어 현재 저장소에서 추적 중이다.
- 시트 크기는 1456×730 픽셀이다. 액션별 프레임 수와 각 프레임의 실제 사각형은 1단계에서 이미지로 확인해 좌표표로 기록한다. 행·열이 균등하다고 가정해 임의로 자르지 않는다.
- 실제 픽셀을 확인한 결과 액션 띠는 위에서부터 5개이고, 각 띠에는 12개 프레임이 가로로 배열되어 있다. 프레임 열 경계는 `x_i = floor(i × 1456 / 12)`이며, i는 0부터 12까지다. 흰 여백을 포함하는 top-origin 액션 행 구간은 `[0, 156)`, `[156, 300)`, `[300, 436)`, `[436, 598)`, `[598, 730)`이다. Pico2D의 bottom-origin 원본 y 좌표는 `730 - row_bottom`으로 변환한다.
- 액션의 의미를 임의로 추정하지 않도록 구현에서는 위에서부터 `액션 1`부터 `액션 5`까지로 표시하고, 실제 프레임 내용은 시트 순서를 그대로 따른다.
- 화면 초기 크기는 기존 뷰어 코드의 800×600을 사용한다. 시트에는 액션명이 표시되어 있지 않아 코드에서는 위에서부터 `액션 1`~`액션 5`로 구분한다.

## 3. 동작 규칙

1. 액션 순서는 시트에 등장하는 5개 액션의 확인된 순서로 고정한다.
2. 각 액션의 프레임을 순서대로 재생하는 것을 1회로 센다.
3. 동일 액션을 정확히 5회 재생한 다음 1초 대기한다.
4. 대기 완료 후 다음 액션의 첫 프레임부터 재생한다.
5. 다섯 번째 액션의 대기가 끝나면 첫 액션으로 돌아간다.
6. 캐릭터의 중심 좌표는 캔버스 중앙 `(400, 300)`으로 고정하고, 확대 시 가로세로 비율을 보존한다.
7. 프레임 재생과 대기 중에도 종료 이벤트를 처리해 창을 정상적으로 닫는다.

## 4. 완료 조건

- 5개 액션이 확인된 순서로 모두 표시된다.
- 각 액션에서 프레임 애니메이션이 정확히 5회 반복된다.
- 각 액션 반복 종료와 다음 액션 시작 사이에 1초 대기가 있다.
- 다섯 번째 액션 다음에 첫 번째 액션으로 돌아가 계속 실행된다.
- 캐릭터는 화면 중앙에 있고, 확대된 이미지가 캔버스 밖으로 잘리지 않으며 종횡비가 유지된다.
- 창 종료 이벤트에 정상 반응하고, 문법 검사 및 준비된 자동/수동 검증을 통과한다.
- 아래 20개 개발 단계를 각각 독립적으로 검증하고 커밋한다. 한 단계의 검증이 실패하면 다음 단계로 진행하지 않고 해당 단계에서 수정 후 재검증한다.

## 6. 구현 및 검증 메모

- 구현은 먼저 한 액션에서 프레임 자르기와 중앙 확대를 확인한 뒤, 반복 횟수와 대기, 다섯 액션 순환을 차례로 더한다.
- 액션의 실제 명칭·행·열·프레임 수는 시트 분석 결과를 기준으로 한다. 좌표를 임의 추정해 구현하지 않는다.
- 시간 대기는 이벤트 처리를 막지 않는 갱신 루프로 구현한다. 반복 도중 종료 이벤트를 놓치지 않도록 한다.
- 각 단계는 변경 범위를 작게 유지하고, 표의 검증 기준을 통과한 경우에만 해당 단계 커밋을 만든다. 커밋 메시지는 실제 변경 내용에 맞춰 조정한다.

## 7. 구현 실행 및 검증 결과

- 실행 명령: `python animation_viewers.py` (`Labs/LEC08_Animation` 폴더에서, Pico2D가 설치된 Python 인터프리터 사용)
- 테스트 명령: `python -m unittest -v test_animation_viewers`
- 시트 픽셀 분석으로 5개 액션 띠와 각 12개 프레임을 확인했으며, 60개 원본 사각형이 시트 경계 안에 있는지 검사했다.
- 테스트는 프레임 순환, 완주 카운터, 두 바퀴 액션 순서, 1초 정지 전후 상태, 표시 비율·크기, 종료 이벤트와 대기 중 캔버스 정리를 확인한다.
- 실제 Pico2D 통합 실행에서 300개 프레임의 순서와 다섯 번의 정지 상태를 확인한 뒤, 한 바퀴 순환 직후 SDL 종료 이벤트로 캔버스가 정리되는 것을 검증했다.
- 각 개발 단계는 검증 후 개별 커밋으로 기록했다. 시작 기준은 `d6a2534`이며, 기획서 작성 커밋 이후 20개의 단계별 구현 커밋을 이어서 만든다.

## 8. 가변 프레임 확장

- 각 액션은 프레임 사각형 `(x, y, width, height)` 목록으로 표현하며, 액션별 프레임 개수는 목록 길이에서 가져온다.
- Mario 시트는 각 셀에서 캐릭터 픽셀 주변만 잘라 프레임별 사각형을 기록했다. 실제 크롭은 60개이며 폭·높이 조합이 48종류다.
- 다른 시트는 `main(animations, sheet_path, sheet_width, sheet_height)`에 사각형 목록과 원본 정보를 전달하거나 `build_grid_animations`에 액션별 프레임 개수를 전달해 사용할 수 있다. 모든 프레임 좌표는 Pico2D의 bottom-origin 기준이다.
- 프레임 크기가 바뀌어도 액션의 최대 프레임 크기로 공통 표시 배율을 계산하므로 재생 중 캐릭터가 프레임마다 최대 크기로 펌핑되지 않는다.
- 회귀 테스트는 1·2·3프레임 액션 조합, 크기가 다른 프레임 렌더링, 5회 재생·정지·액션 순환, 잘못된 사각형을 포함한다.
